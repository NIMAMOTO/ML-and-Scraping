## 実行方法

#### train.py：

1. データの取り入れ
   ライブラリ「pandas」で外部CSVから学習データ・検証データを取り入れ、それぞれのデータの「概要文」と「業界」を分けて変数に入れる。

2. ベクトル化
   scikit-learnのライブラリ「TfidfVectorizer」の関数「fit_transform」で学習データの概要文をベクトル化する。関数「transform」で検証データの概要文をベクトル化する。

3. 学習
   scikit-learnのライブラリ「LogisticRegression」の関数「fit」でX（ベクトル化学習用概要文）をy（学習用業界）に向かわせて学習させる。

4. (option)学習効果の検証

   scikit-learnのクラス「LogisticRegression」のメソッド「score」で学習したデータを検証データを用いて学習効果を見る

5. 正誤表CVSの出力
   scikit-learnのライブラリ「LogisticRegression」のメソッド「predict」で予測を出す
   pandasのメソッド「assign」で予測結果（正誤）を作る
   pandasのライブラリ「DataFrame」で予測結果、予測、正解、概要文という順にDataFrameを作成させる
   pandasのライブラリ「to_csv」でCSVファイルを出力させる

6. 学習させたデータをバイナリ化
   joblibのライブラリ「dump」で文書をベクトル化するライブラリ「TfidfVectorizer」と学習したデータをバイナリファイルに転換する

#### predict.py

1. joblibのメソッド「load」でクラス「TfidfVectorizer」と学習したデータを取り入れる
2. 関数「input」でCLIでユーザーに検証したい業界の概要文の入力をお願いする
3. ユーザーからもらった回答をリストに入れる
4. バイナリしたライブラリ「TfidfVectorizer」のメソッド「transform」でリストにある回答を分割しベクトル化する
5. 「TfidfVectorizer」のメソッド「predict」でユーザーの回答を検証させて、出力する

```
>>>検証したい業界の概要文を入力してください。

>>>予測結果: ['タクシー業界の会社']
```

## 手法

* データ事前処理：TfidfVectorizerを選ぶ理由
  * ベクトル化には CountVectorizer や HashingVectorizer も選択肢としてあるが、IDFによる重み付けで頻出語の影響を抑えられること、語彙が確認可能でデータ規模的にもメモリ制約がないことから TfidfVectorizer を選択した。
* クラスTfidfVectorizerのメソッドanalyzerの３つの分割方法（word、char、char_wb）の中でchar_wbを選ぶ理由
  * wordが使わない理由：analyzerは英語のようなスペースがある文章を処理するとき、wordで処理したら、単語一個ずつちゃんと固まっている。しかし日本語の場合、言葉間のスペースがないゆえ、符号で分けられてしまう（検証済み）。つまり句読点で一個のセンテンスを単位に分割される。そうしてしまうことで、ベクトル化させ、かつ学習させる意味がなくなるので、wordは使ってはいけない。
  * char、char_wb、この２つの選択の中にchar_wbを選ぶ理由：
    charは一個一個の文字を切り分けるものとして、charとchar_wbは基本的な機能としては同じだ。wdはword boundaries（単語境界）という意味で、スペースは人から見ればただの空白ですが、機械に読ませば空白ではなく、一つの符号でスペースを表してる。機械学習において、その符号は機械の学習に役に立たないので、残してもノイズに近いものです。なので、char_wbでスペースをスキップした方が正確率の向上に繋がる。
* なぜngram_rangeの中であえて(1, 3) を選んだ
  * 実験の結果です。分割の数多ければ多くなるほど正確率が上げるわけではないことが実験でわかりましたある境界線を超えたら正確率は下げる。
  * この図から見れば、正確率が最も高いピークは `(1, 3)` と `(2, 2)` の **0.938** です。

| **X \ Y** | **1** | **2**     | **3**     | **4**     | **5**     | **6**     |
| --------- | ----- | --------- | --------- | --------- | --------- | --------- |
| **1**     | 0.932 | 0.936     | **0.938** | 0.930     | 0.928     | 0.916     |
| **2**     | -     | **0.938** | 0.930     | 0.922     | 0.906     | 0.894     |
| **3**     | -     | -         | **0.908** | 0.888     | 0.880     | 0.866     |
| **4**     | -     | -         | -         | **0.860** | 0.840     | 0.832     |
| **5**     | -     | -         | -         | -         | **0.818** | 0.800     |
| **6**     | -     | -         | -         | -         | -         | **0.774** |



* なぜn-gramを選んで、形態素分析を使わない
  * 両方とも試して、正確率の差をみたいと考えたけど、とりあえずもっと軽量なn-gramを使ってみた。まさか簡単に80%を超えたどころか、90%以上まで到達した。納期優先のため形態素分析を試さずに、提出したいと考えている。

* 分類器：なぜLogisticRegression
  * 今回の課題の特徴：
    それぞれのXに対して対応できるyの数は１だけ→ラベル数：１
    yの数は複数ある→データ数：多クラス
  * アルゴリズムとしての特徴：
    ロジスティック回帰もSVMも高次元の特徴を処理するのが得意です。テキスト分類の定番ではある。今回はロジスティック回帰という計算が早いアルゴリズムに決めた。時間があれば両方の正確率効果を比較してみたい気持ちもある。

* dump：なぜjoblib
  * pythonのpickle モジュールでも同じ効果が実現できるのですが、大量な数値配列の扱いが非効率という欠点からjoblibというscikit-learn公式に推奨されている、Numpy配列に専用の方法で書き出すように早く、小さく動く特徴がある

* なぜパイプラインを使用しない
  * 生成したバイナリファイルのサイズは100MBを超えてしまうので、分けたらギリギリ100MB以内です。
